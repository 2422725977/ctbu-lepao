## 日常命令

```bash
cd ~/Documents/校园乐跑
./venv/bin/python lepaorun/driver.py            # 干跑：验 token/跑区/额度/生成轨迹，零写入
./venv/bin/python lepaorun/driver.py --submit   # 正式提交（额度满自动退出 3）
./venv/bin/python stats.py                      # 学期进度
LEPAO_FORCE=1 bash ~/.hermes/scripts/lepao_tick.sh   # 立刻走一遍 tick，跳过随机时刻判定
```

driver 的 `EXIT` 码：`0` 成功/干跑、`2` token 死、`3` 当日额度已满、`4` 接口异常。

## 抓 token（最高频的坑，按顺序做）

1. **起 mitm，务必带端口匹配**：

```bash
cd ~/Documents/校园乐跑 && ./venv/bin/mitmdump -p 8888 \
  --mode upstream:http://127.0.0.1:7897 \
  --set confdir=$HOME/.mitmproxy --ssl-insecure \
  --allow-hosts '^(.*\.)?ctbu\.edu\.cn(:\d+)?$' \
  -w flows/cap_$(date +%H%M).mitm --set flow_detail=1
```

   - `--allow-hosts` 匹配的是 **`host:port`**：写成 `ctbu\.edu\.cn$` 只会变纯隧道，一条 flow 都不落。
   - 必须带 `--mode upstream:http://127.0.0.1:7897`（Clash），否则 mitm 解析到校内 IPv6 连不上，curl 返回 000。
   - 8888 常被上一轮残留进程占用（`address already in use`）→ 先 `pkill -f 'mitmdump -p 8888'`。

2. **系统代理指到 8888**（服务名是 Wi-Fi，别写 Ethernet）：

```bash
networksetup -setwebproxy "Wi-Fi" 127.0.0.1 8888; networksetup -setsecurewebproxy "Wi-Fi" 127.0.0.1 8888
networksetup -setwebproxystate "Wi-Fi" on; networksetup -setsecurewebproxystate "Wi-Fi" on
# 事后必须复原：
networksetup -setwebproxy "Wi-Fi" 127.0.0.1 7897; networksetup -setsecurewebproxy "Wi-Fi" 127.0.0.1 7897
```

3. **让流量出现**：电脑端企业微信 → 工作台 →「智慧体育」打开小程序
   （工作台窗口在 (1280,390) 1280×941 时，全局点 (1964,526) 就是该卡片）。
   够用的流量是**任意已登录请求**——请求体里就带 token，不必抓登录流程。

4. **取 token**：`./venv/bin/python grab_token.py flows/cap_x.mitm`
   优先解密请求体 `ostype=5&data=<AES>`（每条都含 `uid/token/student_num`），退化才看登录响应。

5. **写回 config.json** 的 `accounts.2025410030.auth`，再干跑一次，看到 `[0] token 有效` 才算成功。

### token 语义

- 合法 token 即过，与 IP/设备/Cookie 无关；**单活动会话**：任何地方重新登录（含手机小程序）立刻把旧 token 顶死。
- **提交不消耗 token**：同一天提交后再干跑仍有效（2026-10-29 实测）——日常只需抓一次号。

## 自动定时（cron 设计）

- Hermes 任务 `dae13f7edf0a`：`*/5 12,13,18-22 * * *`，`no_agent=true` + `script=lepao_tick.sh`。
- 随机时刻由 tick.py 按 (日期, 窗口) 做 sha256 种子算出，**全天恒定**；cron 只负责每 5 分钟问「到点没」。
  这样休眠醒来、错过时刻也能在窗口内补跑，且不需要长 sleep 进程。
- 两个窗口各一个随机点（12:00–14:00 / 18:00–22:30）；上界取窗口末 −5 分钟，避免落到没有 tick 的分钟。
- 状态文件 `state/auto_state.json`：`done` 后当天静默；`dead_notified` 防 token 死刷屏。
- tick 空输出 → cron 不推送（静默看门狗）；成功才推完整数据（距离/用时/配速/时间窗/记录号/审查状态/学期累计）。
- 投递写 `origin,qqbot:A6D673752C392416B4AE9E5824917E07`：**微信 iLink 常报 `session not ready`（要先让 bot 收到他的一条消息），别只写微信。**

## 服务端规则（2026-10 实测，beforeRunV260）

| 项 | 值 |
|---|---|
| 跑步时段 | `run_start_time 18000`–`run_end_time 81000` = 05:00–22:30 |
| 距离 | 2.50–10.00 km |
| 配速 | 180–540 s/km（3'0"–9'0"） |
| 每日上限 | **1 次计入成绩**；第 2 次 stopRun 仍成功但返回 `record_status 0` + `record_failed_reason: 当天关联成绩次数已达到上限` |
| 学期 | term_id 4773，term_num 40 次 |
| 无效记录 | 也计入 `getTermRunRecord` 条数（driver 的「今日已完成 N 次」会显示 2），但只有 status 1 算成绩 |

## 坑清单

1. **别指望 `git clone`**：本机到 github.com:443 常超时；`gh api` 通。拉包用
   `gh api repos/O/R/zipball/main > x.zip`，中文文件名先按 cp437→gbk 解码再解压。
2. **Hermes cron 用的 python 不是 anaconda**，依赖库不在；需要 venv 的脚本必须写成 `.sh` 包一层绝对路径。
3. **GUI 点击**：cua-driver 的 CGEvent 打不进企微小程序窗口；用 `swift` 脚本发
   `CGWarpMouseCursorPosition` + `CGEvent(mouseType:.leftMouseDown).post(tap:.cghidEventTap)` 才灵。
   窗口被隐藏时截图返回 0×0，先 `open -a 企业微信` 再点。
4. **小程序跑步页卡死（退不出跑步）**：点「结束跑步」→「距离过短，此次记录将不会保存」→ 确认后又回到跑步页，死循环。
   清 WebKit 缓存（`~/Library/Containers/com.tencent.WeWorkMac.MiniProgram/Data/Library/WebKit/WebsiteData`）**无效**；
   服务端也没有「进行中」记录（`total_num/run_num/run_distance` 只反映已提交记录）。属于客户端 bug，不影响接口打卡；
   别在这上面耗时间，重装企业微信或等次日新记录顶掉。
5. **别在手机上登录小程序**：会立刻顶掉电脑 token，任务次日报「token 失效」。他常说「我检查一下」——那就是要重抓号。
6. 抓完号务必复原系统代理（7897），否则他一上网就觉得卡。
