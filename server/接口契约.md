## 2. GET /api/dashboard 契约

### 2.1 数据来源（全部本地、只读、零网络调用）

| 来源 | 用途 |
|---|---|
| `$LEPAO_DATA/accounts.json` | 账号列表、`enabled`、`auth.token`（仅取前 8 位）、`auth.issued_at`、`name`/`alias` |
| `$LEPAO_DATA/state/<student_num>_state.json` | `date` / `done` / `failed_count` / `last_exit` / `last_run` / `dead_notified` |
| `$LEPAO_DATA/logs/server_YYYYMMDD.log` | 最近执行动态、告警线索、日志尾部 |
| `DEFAULT_WINDOWS` | 时间窗列表 |
| `daily_target("noon", 12, 0, 14, 0, student_num)` | `today.target_time`（与调度器同一算法/同一日期种子，全天恒定） |

文件不存在 / 损坏 / 并发写半成品一律容错：`logs_tail`、`recent_events` 返回 `[]`，数值返回 `0`，不抛 500、不编造数值。聚合整体异常时返回固定键结构的 `health="error"` 错误态（§5 五态要求）。

### 2.2 顶层字段（键名固定）

| 字段 | 类型 | 说明 |
|---|---|---|
| `server_time` | string `YYYY-MM-DD HH:MM:SS` | 服务器当前时间，Asia/Shanghai |
| `data_time` | string | 数据时点 = `accounts.json` / `*_state.json` / 当日日志中最新的 mtime；无数据则回退 `server_time` |
| `env` | string | 默认 `"production"`，可由 `LEPAO_ENV` 覆盖 |
| `health` | `"ok" \| "degraded" \| "error"` | `error`=accounts.json 不可读；`degraded`=存在失效凭证 / 缺凭证 / error 级告警；否则 `ok` |
| `summary` | object | 见 2.3 |
| `windows` | array | 见 2.4 |
| `accounts` | array | 见 2.5 |
| `alerts` | array | 见 2.6 |
| `recent_events` | array | 见 2.7 |
| `logs_tail` | array&lt;string&gt; | 当日日志最后 50 行（已脱敏），文件不存在返回 `[]` |
| `public_base_url` | string | **附加字段**，`PUBLIC_BASE_URL`，默认 `""` = 同源；前端可忽略 |
| `read_only` / `permissions.write` | bool / bool | **条件附加字段**：仅 `LEPAO_READ_ONLY=true` 时下发 `read_only:true` + `permissions.write:false`；默认**不下发**，见 §4.1 |

> 默认响应结构不含 `read_only` / `permissions`，保证「不改动后端 API 契约」；开启开关时也只是新增字段，既有字段一律不变。

### 2.3 `summary`

| 字段 | 口径 |
|---|---|
| `accounts_total` | `accounts[]` 长度 |
| `enabled` | `enabled=true` 的账号数 |
| `today_done` | 当日 state 中 `done=true` 的账号数（exit 0 成功与 exit 3 额度已满都置 done，与调度器状态机一致） |
| `today_total` | 等于 `enabled`（当日应参与调度的账号数） |
| `alerts_count` | `alerts[]` 长度 |
| `term_total` | 学期总次数；当前固定 `0` |
| `term_valid` | 学期达标次数；当前固定 `0` |
| `term_target` | `40`（设计规格 §7） |
| `stat_caliber` | **附加字段**，口径声明字符串 |

**统计口径（强制）**：仅 `record_status = 1` 计入达标与有效里程，无效记录计入总次数但不计入达标。`getTermRunRecord` 是需要凭证的网络接口，`/api/dashboard` 不调用；当前 `state/` 无学期记录明细，因此 `term_total` / `term_valid` 回退为 **0**，并在 `stat_caliber` 中明确标注，绝不编造数值。若后续 state 中出现 `records[]`（含 `record_status`）或 `term_total`/`term_valid` 汇总字段，聚合器会按上述口径真实计算（见 `server.py: _term_stats`）。

### 2.4 `windows`

直接由 `DEFAULT_WINDOWS` 生成，不硬编码：

```json
[{"name":"noon","start":"12:00","end":"14:00"},
 {"name":"evening","start":"18:00","end":"22:30"}]
```

> `today.target_time` 按当前调度器实际使用的 **noon 窗口**（`daily_target("noon",12,0,14,0,学号)`）计算；evening 窗口仅作展示。此为遵循「调度语义不动」的有意选择。

### 2.5 `accounts[]`

| 字段 | 类型 | 说明 |
|---|---|---|
| `student_num` | string | 学号 |
| `name` | string | `name` 优先，回退 `alias` |
| `enabled` | bool | — |
| `token_prefix` | string | `auth.token[:8]`，**永不返回完整 token** |
| `token_issued` | string | `auth.issued_at` 原值 |
| `credential` | `"ok" \| "dead" \| "unknown"` | 见下 |
| `today` | object | `{done, target_time:"HH:MM", status, status_label, last_exit:int\|null, failed_count:int, dead_notified:bool}` |
| `last_result` | object | `{exit_code:int\|null, summary:string}`，业务化文案见 §5 映射 |

**`credential` 推断规则（不硬编码「有效」）**：
1. 无 token → `unknown`；
2. state 的 `dead_notified` / `token_dead` / `last_exit=2`，或当日日志中该学号出现 `TOKEN_DEAD` 且时间不早于 `issued_at` → `dead`；若凭证在 TOKEN_DEAD 之后被重新签发（`issued_at > last_run`），该线索失效；
3. `issued_at` 缺失或不可解析 → `unknown`；
4. 签发超过 `TOKEN_STALE_DAYS`（默认 7 天）且无有效证据 → `unknown`（不宣称有效）；
5. 其余（有 token、近期签发、无失效线索）→ `ok`。

**`today.status`** 取设计规格 §5 六类状态的**机器键**（与前端 `STATUS` 映射一致，中文标签由前端统一渲染）：

| 机器键 | 中文徽章 | 触发条件 |
|---|---|---|
| `ok` | 正常 | `done=true`（含 exit 0 成功 / exit 3 额度已满） |
| `pending` | 待执行 | 未到目标时刻、无失败记录 |
| `running` | 运行中 | 已到目标时刻、调度中但尚无成功结果（推断态，非真实进程态） |
| `attention` | 需关注 | `last_exit=2` / `credential=dead` / `failed_count>0` |
| `error` | 失败 | `last_exit=4` |
| `disabled` | 已停用 | `enabled=false` |

`today.status_label` 为**附加字段**，给出对应中文名称（便于运维/其他消费方直接读取），前端可忽略。

### 2.6 `alerts[]`

`{level:"error"|"warn"|"info", message, student_num, time}`，按 `(student_num, message)` 去重（M05）。来源：凭证失效 / 状态未知 / 未配置凭证 / 当日额度已满 / 接口异常 / 累计失败。

### 2.7 `recent_events[]`

`{time, level:"error"|"warn"|"info"|"success", student_num, message}`，解析当日日志行（`[学号]` 前缀提取为 `student_num`），**最新在前，最多 30 条**；文件不存在返回 `[]`。

### 2.8 退出码 → 业务语言（设计规格 §5）

| exit | `last_result.summary` / 告警文案 | 动作 |
|---|---|---|
| 0 | 提交成功，等待审查；仅 `record_status=1` 计入成绩与达标 | 展示距离·用时·配速·记录号（由上游提交结果提供） |
| 2 | 凭证失效：重新抓号后可恢复，请更新凭证 | 提供「更新凭证」 |
| 3 | 当日额度已满：无需重试，次日自动恢复 | 禁用提交并解释原因 |
| 4 | 接口异常：已生成告警，请查看日志或重试 | 提供「查看日志 / 重试」 |
| 其他 | 执行失败（exit=N）：请查看日志或重试 | 不暴露原始异常栈 |

| `LEPAO_READ_ONLY` | `false` | compose（可选） | **可选只读展示开关**；`true` 时 `/api/dashboard` 下发 `read_only:true` + `permissions.write:false`，默认不下发。识别值：`1`/`true`/`yes`/`on`（大小写不敏感） |

### 4.1 可选只读展示开关（`LEPAO_READ_ONLY`）与加固方式

**背景（主理人拍板）**：不采用「默认只读」方案。理由是硬约束为「以仓库现状为基础 + 不改动后端 API 契约」，原仓库 `/api/submit` 与 `/api/token` 本就是无鉴权可写；设计规格 §3 的 M04 / M07 / M12 明确要求行内操作与批量操作入口，默认锁死会让管理台失去核心功能。因此只读做成**可选开关**。

| 取值 | `/api/dashboard` 响应 | 前端行为 | 写接口实际可用性 |
|---|---|---|---|
| `false`（默认，或不设置） | **不**下发 `read_only` / `permissions` 字段 | 保持全部写入口可用（M04 / M07 / M12） | 可写（与仓库现状一致） |
| `true` / `1` / `yes` / `on` | 新增 `read_only:true`、`permissions:{"write":false}` | 庖丁的 `evaluateReadOnly()` 已兼容，自动进入只读态、禁用写入口与二次确认 | **仍可写**（开关只驱动展示态） |

**启用方式**（compose 的 `environment` 段，默认注释、不启用）：

```yaml
# - LEPAO_READ_ONLY=true
```

**加固方式（三层，按强度递增）**：
1. **展示层（本次已实现）**：`LEPAO_READ_ONLY=true` 让前端进入只读态，避免误操作；**这不是安全边界**，直接调用 `/api/token` 或 `/api/submit/<id>` 仍然有效。
2. **网络层（推荐，运维按需启用）**：在 Nginx 拦截所有非 `GET`/`HEAD` 请求，注释片段见 §8.1，默认不启用。端口已绑定 `127.0.0.1:8080:8080`，公网只有 Nginx 一个入口，因此该层是有效的强制边界。
3. **认证层（后续改造）**：补登录鉴权与对象级权限；本次硬约束不引入，属待确认项。

> 注意：`LEPAO_READ_ONLY` 只新增响应字段，**不拦截任何写请求、不改变 `/api/token` / `/api/submit/<id>` 的请求参数与响应结构**，因此默认与开启两种模式均满足旧契约零变更。服务端不做强制 403，是主理人「不改动后端 API 契约」拍板的直接结果。

## 6. 静态资源 URL 清单

| URL | 实际文件（宿主） | 容器内路径 |
|---|---|---|
| `/static/dashboard.css` | `server/static/dashboard.css` | `/app/static/dashboard.css` |
| `/static/dashboard.js` | `server/static/dashboard.js` | `/app/static/dashboard.js` |

模板应使用 `{{ url_for('static', filename='dashboard.css') }}` 生成**同源相对路径**。仓库内不引入 CDN、绝对域名或 IP。`ProxyFix`（`x_for=1, x_proto=1, x_host=1`）保证反代下生成的 URL 与 scheme 正确。

**构建前置条件**：`server/templates/dashboard.html` 与 `server/static/`（至少含上述两个文件）必须在 `docker compose build` 之前存在，否则 `COPY server/static/` 会因源目录缺失导致构建失败。

## 7. 域名字段出现位置

- 业务代码 `server/server.py`：**0 处**硬编码目标域名或服务器 IP。
- `server/Dockerfile` / `server/docker-compose.yml`：**0 处**。
- 目标域名应且仅应出现在**仓库外**的部署层：Nginx `server_name`、DNS 解析记录、TLS 证书配置、以及可选的 `PUBLIC_BASE_URL` 环境变量值。
- `PUBLIC_BASE_URL` 是唯一允许承载展示用基址的字段，且默认空（同源），不影响路由与静态资源 URL。

## 8. 反向代理、安全头与缓存策略

- 端口绑定：`127.0.0.1:8080:8080`，**不监听 `0.0.0.0`**；公网仅经 Nginx 反代暴露。
- Nginx 需透传：`X-Forwarded-For`、`X-Forwarded-Proto`、`X-Forwarded-Host`（各 1 层，与 `ProxyFix` 信任层数一致）。
- Flask 响应头：`X-Content-Type-Options: nosniff`、`Referrer-Policy: strict-origin-when-cross-origin`。
- 缓存：`/api/*` 设 `Cache-Control: no-store`（保证 30s 局部刷新读到实时状态）；`/static/*` **移除** Flask 默认的 `no-cache`，不设任何强制缓存头，长期缓存完全交由 Nginx `location /static/` 处理。
- HEALTHCHECK（镜像内 + compose）：`GET /api/status`，60s 间隔、5s 超时、10s 启动宽限。

### 8.1 【P0 待确认风险】公网写接口无鉴权 + 可选 Nginx 拦截片段

**风险等级：P0（待用户确认）**。`/api/token`（写入/新建账号凭证）与 `/api/submit/<student_num>`（触发一次真实乐跑提交）**没有任何鉴权**。公网经 Nginx 反代后，任何能访问该域名的人都可以调用；`LEPAO_READ_ONLY` 只是前端展示开关，**不是安全边界**。

**主理人拍板**：本次按「以仓库现状为基础 + 不改动后端 API 契约」保持原样，不默认只读、不在服务端加 403；真实部署前需由用户确认设计规格 §8 的使用边界与授权范围（仅本人或已明确同意的成员、仅供学习研究、风险自负）。

以下为**注释形式、默认不启用**的 Nginx 加固片段，供运维参考。**整段全部被 `#` 注释，不会生效；本仓库不加载、不自动下发**。启用前请在测试环境验证，并确认会因此失去 M04 / M07 / M12 的写入能力。

```nginx
# ---------------------------------------------------------------------------
# [P0 可选加固] 拦截所有非 GET / HEAD 请求 —— 默认整段注释，不启用
# 启用前置条件：用户已确认设计规格 §8 的使用边界与授权范围
# 启用后影响：/api/token、/api/submit/<id> 返回 405，管理台写入口不可用
```

## 9. 部署前置条件

1. `server/templates/dashboard.html`、`server/static/dashboard.css`、`server/static/dashboard.js` 已由前端交付（见 §6）。
2. `server/data/accounts.json` 存在且含真实 token；`server/data/state`、`server/data/logs` 目录存在（compose 会自动创建后两者）。

4. **`/app/config.json` 本次不修、不挂载 sample（主理人拍板）**：`driver.load_config()` 读取 `/app/config.json`。当前 Dockerfile 未 COPY 该文件（与改造前一致），也**不**把 `lepaorun/config.sample.json` 当配置挂进镜像 —— 挂载占位配置会让提交类接口真的向外部发起请求，超出本次「页面还原与域名适配」边界，且属仓库既有行为。因此 `/api/submit` 与调度器实际提交在**未提供生产 `config.json`** 时会失败（`FileNotFoundError` → 500 / 异常日志）；看板 `/`、`/api/status`、`/api/dashboard` 与静态资源不依赖该文件，可正常工作。启用提交能力前，需**用户自行提供生产配置**并确认设计规格 §8 的使用边界与授权范围。详见 §10。
5. 系统 `tzdata` 由 Dockerfile 安装；`TZ=Asia/Shanghai` 必须保持，否则调度日期种子与日志日期错位。
6. 合规（设计规格 §8）：页脚常驻 `LRL-1.0 衍生版 · 原作者 dan-cun / lepao3 · 仅供学习研究 · 不提供商业授权 · 风险自负`；仅本人或已明确同意的成员；token 不外传、不提交仓库、界面只显示前缀；真实部署前确认使用边界与授权范围。
