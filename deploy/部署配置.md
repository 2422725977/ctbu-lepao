# CTBU 乐跑主页管理系统 · codexi.cn 部署配置

> 只记录本项目可落地的配置项与命令，不是通用部署教程。
> 环境已实测：腾讯云 Lighthouse 成都 / 公网 IP `140.143.87.163` / OpenCloudOS 9.6 / 宝塔 Nginx（`/www/server/nginx/conf/nginx.conf:99` 通配 include vhost）/ Docker 29.7.2 + Compose / **8080 空闲**。
> 当前状态：**域名未备案**，只启用 80，443 与证书全部注释未启用；验证走 Host 头，不走域名解析。

## 1. 域名相关配置项（逐项）

| # | 配置项 | 值 / 落地位置 | 校验与备注 |
|---|---|---|---|
| 1 | DNS A 记录 `codexi.cn` | `140.143.87.163`，阿里云万网（hichina），已生效 | 备案前大陆节点按域名访问 80/443 会被拦截，DNS 生效 ≠ 可访问 |
| 2 | DNS A 记录 `www.codexi.cn` | 同上，已生效 | 与 `server_name` 一一对应 |
| 3 | ICP 备案 | **未完成** | 备案前只能用 `curl -H 'Host: codexi.cn' http://127.0.0.1/` 或 `http://140.143.87.163` 验证；**不要**据此判定站点故障 |
| 4 | `server_name` | `codexi.cn www.codexi.cn;`（vhost 第 1 个 server 块） | 不加 `default_server`，避免抢宝塔 80 上其他站点；面板若另有同名站点会产生 `conflicting server name`，脚本会警告但不自动删 |
| 5 | `listen` | `80` | 443 server 块整段注释，未启用证书路径 |
| 6 | 宝塔 include | 主配置第 99 行 `include /www/server/panel/vhost/nginx/*.conf;`（http 块内） | **不改主配置**；装完执行 `nginx -t && nginx -s reload`；PATH 里没有 nginx 时用 `/www/server/nginx/sbin/nginx` |
| 7 | Host 头 | Nginx `proxy_set_header Host $host;` | 后端 `ProxyFix(x_host=1)` 还原域名；验证 `curl -H 'Host: codexi.cn' http://127.0.0.1/` |
| 8 | `X-Real-IP` | `$remote_addr` | 供日志与后端取真实来源 |
| 9 | `X-Forwarded-For` | `$proxy_add_x_forwarded_for` | 与 `ProxyFix(x_for=1)` 配套：追加后取**最右**值，客户端伪造 XFF 不生效；不要再叠 CDN / 二级反代 |
| 10 | `X-Forwarded-Proto` | `$scheme`（当前 `http`） | 备案启用 443 后自动变 `https`，`ProxyFix(x_proto=1)` 还原，无需改代码 |
| 11 | `X-Forwarded-Host` | `$host` | `ProxyFix(x_host=1)` |
| 12 | 反代目标 | `http://127.0.0.1:8080` | compose 绑定 `127.0.0.1:8080:8080`，**8080 不监听 0.0.0.0**，禁止公网直连 |
| 13 | `PUBLIC_BASE_URL` | **留空**（`server/docker-compose.yml` 中是注释行） | 空 = 同源相对链接；域名**只**允许出现在 Nginx / DNS / 证书层，`server/` 业务代码 0 处硬编码。仅当页面需要绝对展示链接时才开启 |
| 14 | 静态资源路径 | `/static/dashboard.css`、`/static/dashboard.js`（同源相对路径，由模板 `url_for`/固定相对路径生成） | Nginx `location /static/` 反代 + `expires 7d` + `Cache-Control "public, max-age=604800"`；**文件名无内容 hash，不用 immutable**；改前端后需强刷或改文件名，否则 7 天内命中旧缓存 |
| 15 | API 缓存 | 后端对 `/api/*` 下发 `Cache-Control: no-store` | Nginx 不覆盖；保证 30s 局部刷新读到实时状态 |
| 16 | 安全头 | `X-Content-Type-Options: nosniff`、`Referrer-Policy: strict-origin-when-cross-origin` | Nginx 侧用 `proxy_hide_header` 隐藏后端同名头后重新 `add_header`，避免重复；`/static/` location 内重复声明一份（Nginx add_header 不跨级继承） |
| 17 | 写接口加固 | **注释状态、默认不启用** | 取消 vhost 中 `location ~ ^/api/(token\|submit/)` 整段注释 → 非 GET/HEAD 一律 403；启用后抓号客户端也无法公网推 token，需走本机 `127.0.0.1:8080` 或内网。启用后 `nginx -t && nginx -s reload` |
| 18 | 未备案验证 | `curl -H 'Host: codexi.cn' http://127.0.0.1/` | 见 §2 完整命令；`http://140.143.87.163/` 只用于确认 80 放行，会命中宝塔默认站点而非 dashboard |
| 19 | 备案后 HTTPS | 取消 vhost 末尾 443 server 块注释 → 填证书路径 → 80 块改 `return 301 https://$host$request_uri;` → `nginx -t && nginx -s reload` | 证书路径目前**全部注释未启用**；`X-Forwarded-Proto` 自动变 https；`PUBLIC_BASE_URL` 仍建议留空 |

**未备案下的完整验证命令**（在服务器上执行，全部走本机回环 + Host 头）：

```bash
HOST='codexi.cn'; BASE='http://127.0.0.1'
for p in / /static/dashboard.css /static/dashboard.js /api/status /api/dashboard; do
  printf '%-26s %s\n' "$p" "$(curl -s -o /dev/null -w '%{http_code}' -H "Host: $HOST" "$BASE$p")"
done
curl -sS -o /dev/null -w 'www: %{http_code}\n' -H 'Host: www.codexi.cn' http://127.0.0.1/
curl -sI -H "Host: $HOST" http://127.0.0.1/static/dashboard.css | grep -iE 'HTTP/|cache-control|expires|x-content-type|referrer-policy'
curl -s -H "Host: $HOST" http://127.0.0.1/api/dashboard | python3 -m json.tool | head -60
curl -sI http://140.143.87.163/ | head -5     # 仅确认 80 放行，命中宝塔默认站点属正常
```

### 2.2 `/api/dashboard` 字段（键名固定）

```bash
curl -s -H 'Host: codexi.cn' http://127.0.0.1/api/dashboard \
  | python3 -c "import json,sys; d=json.load(sys.stdin); print(sorted(d.keys()))"
curl -s -H 'Host: codexi.cn' http://127.0.0.1/api/dashboard \
  | python3 -c "import json,sys; d=json.load(sys.stdin); print(d['health'], d['summary'], d['windows'], [a['today']['status'] for a in d['accounts']])"
```

必备顶层键：`server_time`、`data_time`、`env`、`health`、`summary`、`windows`、`accounts`、`alerts`、`recent_events`、`logs_tail`、`public_base_url`。
`summary` 需含 `accounts_total / enabled / today_done / today_total / alerts_count / term_total / term_valid / term_target(=40) / stat_caliber`；`windows` 两条（`noon 12:00–14:00`、`evening 18:00–22:30`）；`accounts[].today` 需含 `status / status_label / target_time / last_exit / failed_count`；响应**永不返回完整 token**（仅 `token_prefix`）。
`health` 取值 `ok | degraded | error`；聚合异常时仍返回固定键结构而不是 500。

## 3. 回滚方式

**三种粒度，按影响面从小到大；三种都不删数据。**

### 3.1 停用站点（最快，容器保留）

```bash
mv /www/server/panel/vhost/nginx/codexi.cn.conf \
   /opt/ctbu-lepao-backups/codexi.cn.conf.$(date +%Y%m%d-%H%M%S).disabled
nginx -t && nginx -s reload      # 若 PATH 无 nginx，用 /www/server/nginx/sbin/nginx
```
此时 `127.0.0.1:8080` 仍可直连，域名 Host 请求落回宝塔默认站点。恢复：把 `.disabled` 文件移回原位并 reload。

### 3.2 切回上一个 commit（保留容器与全部运行数据）

```bash
cd /opt/ctbu-lepao
git log --oneline -5                     # 记下要回退的 commit
TS=$(date +%Y%m%d-%H%M%S)
cp -p server/data/accounts.json /opt/ctbu-lepao-backups/accounts.json.pre-rollback.$TS   # 不打印内容
git reset --hard <上一个 commit>
cp -p /opt/ctbu-lepao-backups/accounts.json.pre-rollback.$TS server/data/accounts.json  # 还原运行数据
docker compose -f server/docker-compose.yml up -d --build
bash deploy/deploy.sh                    # 若要连 vhost 一起回到分支版本，改跑这条幂等脚本
```
`reset --hard` 会覆盖被仓库跟踪的 `accounts.json`，**必须**先备份再还原（脚本 §1 已内置同样的保护）。
若同时要回退 vhost，先按 §3.1 停用，再 `cp /opt/ctbu-lepao-backups/codexi.cn.conf.*.bak /www/server/panel/vhost/nginx/codexi.cn.conf && nginx -t && nginx -s reload`。

### 3.3 完全下线（保留数据卷）

```bash
docker compose -f /opt/ctbu-lepao/server/docker-compose.yml down
# 恢复：docker compose -f /opt/ctbu-lepao/server/docker-compose.yml up -d
```
`down` 只停容器；`state/`、`logs/`、`accounts.json` 是 bind mount 到 `/opt/ctbu-lepao/server/data/`，不会消失。
**禁止**：`docker compose down -v`、`docker volume prune`、`rm -rf server/data`、`git clean -fd`（会清掉未跟踪的 state/logs）。

## 4. 已知边界与待确认项

| 项 | 现状 / 影响 | 待确认动作 |
|---|---|---|
| 未备案 | 大陆节点按 `codexi.cn` 访问 80/443 会被拦；443 server 块与证书路径全部注释未启用 | 完成 ICP 备案后按 §1 #19 启用 HTTPS；备案前验收只认 Host 头命令 |
| 公网写接口无鉴权 | `POST /api/token`、`POST /api/submit/<student_num>` 经反代后公网可直调，无登录、无限流 | 主理人决策是否启用 vhost 里注释态的 403 加固片段；启用后抓号推送改走本机/内网 |
| `LEPAO_READ_ONLY` 不是安全边界 | compose 里是注释行（默认 `false`）；设 `true` 只让 `/api/dashboard` 多下发 `read_only:true` / `permissions.write:false`，驱动前端只读态，**不拦截任何写请求** | 若启用 403 加固片段，可在 compose 同时设 `LEPAO_READ_ONLY=true` 使前后端展示一致；`server/接口契约.md` §8 的参考片段返回 405 且为 443 示意，本部署文件按分派要求返回 403，两者择一启用、不要叠加 |
| `config.json` 未提供 | Dockerfile 未 COPY `/app/config.json`，`driver.load_config()` 读不到 → `/api/submit` 与调度器的实际提交会 500；`/`、`/api/status`、`/api/dashboard` 不依赖它 | 是否挂载由 `lepaorun/config.sample.json` 派生的 `/app/config.json`（需改 compose，本次未动 `server/`） |
| Flask 内置服务器 | `CMD python -u /app/server.py` 单进程 + 后台调度线程；换 Gunicorn 多 worker 会导致调度器缺失或重复提交 | 后续改造需先把调度器拆成独立进程；本次保持现状 |
| `term` 统计恒 0 | `state/` 无学期记录明细，`term_total/term_valid` 固定 0，并在 `summary.stat_caliber` 标注口径，不编造数值 | 如需真实趋势，须由独立任务落盘 `records[]` 到 `state/` |
| 静态缓存无版本号 | `dashboard.css/js` 文件名无 hash，命中 7d 缓存后前端改动不会立即生效 | 上线新前端后强刷，或改文件名/加查询串并同步模板 |
| 日志 | 应用日志落在 `server/data/logs/server_YYYYMMDD.log`（容器只解析当日），宿主机无自动轮转；Nginx 日志在 `/www/wwwlogs/` | 用宝塔「日志切割」或 logrotate 配保留策略，并巡检 `df -h`；容器日志走 `docker compose logs` |
| 运行数据安全 | `server/data/accounts.json` 含真实 token 且被 PUBLIC 仓库公开跟踪 | 脚本不打印内容、`reset --hard` 前保护性备份还原；禁止把服务器运行数据再提交回公开仓库 |
| 时区 | `TZ=Asia/Shanghai` + Dockerfile 安装系统 tzdata，调度日期种子与日志文件名依赖它 | 不要删 tzdata 安装步骤 |
| 自启 | 容器 `restart: unless-stopped`，Nginx 由宝塔托管；**本轮未做重启恢复演练** | 上线后择机 `reboot` 验证 `docker compose ps` 与 `nginx -t` 均恢复 |

## 5. 上线执行顺序（主理人按序执行）

1. **本地**：把本轮改造连同 `deploy/` 三个文件推到分支 `deploy/codexi`（PUBLIC 仓库：`https://github.com/2422725977/ctbu-lepao.git`）。
2. **服务器首次引导**（脚本自身来自仓库，必须先手动 clone 一次）：
   ```bash
   git clone -b deploy/codexi --depth 1 https://github.com/2422725977/ctbu-lepao.git /opt/ctbu-lepao
   chmod +x /opt/ctbu-lepao/deploy/deploy.sh
   ```
3. **执行上线**（root；会重建容器，秒级中断）：
   ```bash
   sudo bash /opt/ctbu-lepao/deploy/deploy.sh
   ```
   脚本会先把自身复制到 `/tmp` 再运行副本，避免第 1 步 `git reset --hard` 覆写正在执行的脚本；副本退出时自动清理。
   之后任何重复执行都走 `git fetch origin deploy/codexi && git reset --hard origin/deploy/codexi` 幂等路径，无需再手动 clone。
4. **验收**：按 §1 末尾「未备案下的完整验证命令」+ §2 清单逐项核对（脚本 §7 已自动断言 6 个 200、缓存头、`/api/dashboard` 固定键、LRL-1.0 页脚、无 meta refresh）。
5. **备案后**再按 §1 #19 启用 443 / 证书，并复核 `X-Forwarded-Proto` 变为 https。
6. **演练**：择机 `reboot` 复核容器与 Nginx 恢复（§4 最后一行）。

> 本轮只产出文件，**未执行任何服务器操作**；以上命令由主理人联调通过后统一执行。
